Hello everyone! I hope all of you who are reading this are in good health and having a wonderful day! My name is Jody ritonga from Indonesia. And for todays writing. I will share you my bug bounty writeup which i’ve found one week ago in one of indonesian new startup.

I’m absolutely fascinated by this type of bug because it’s mind-boggling how numerous developers end up making the same mistake, albeit with different methods. It never ceases to amaze me! Anyway, enough talking. There isn’t much need for explanation about the bug since its name is self-explanatory. So, let’s dive into how I stumbled upon it.

  1. As usual, my methodology when approaching a website is always to check the password reset functionality first. I explore questions such as: Do they have a rate limit in place? Can I manipulate the reset link through poisoning techniques? And so on.
  2. And yes. At first time trying, i’ve found no rate limit and can lead to email flooding type of bug. Usually i immediately make the report and send it into the company, but at that time my reaction like

3. And then i’ve try tinkering around the link of the reset password functionality. I click on the reset password and try to change it. Before i click okay i send it to the burp intruder, and than, i see something fishy on the request. It looks something like this

4. Does your hacker mindset already tingling? If it’s tingling, damn your hacker sense is very good. The problem is on the user_id part. When i saw that, my mind was like can i change the password of user B through user A just by changing the ID on reset password?

5. So i already make two account. User A and user B. And the most dangerous part is that the user_id is a predictable id. So let say i create user A and the id is 123, when i create user B account the id will be 125. It will increase by 2. I can just changing all of user password in the database with that kind of id.

6. So i send reset password Through user A. When i already set the password, i turn on my burp intruder, and change the id to user B id. And forward the request and then boom. It works ! I just change user B password through link reset password from user A.

Remediation

So the problem on this is that the developer make the id predictable and didn’t have enough authorization system. Developer need to make sure that when user using the reset password link, it only work on user account and not others.

I immediately make the report and send it to the company IT team, and they paid me well $$$. So thats all for today my fellow reader !
