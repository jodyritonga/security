Human-led / LLM-accelerated / evidence-gated

The model proposes. The evidence decides.

LLMs help navigate large systems and generate adversarial hypotheses. They do not decide whether a candidate is reachable, exploitable, impactful, or novel.

01 / Scope

Start with the security promise.

Define the target, authorized attacker, controlled inputs, protected assets, and concrete consequences that matter before searching for code.

02 / Threat model

Rank boundaries, not buzzwords.

Map product journeys, identities, capabilities, data lifetimes, and guard conditions. Select a narrow slice where failure would cross real authority.

03 / LLM assistance

Use models for focused reasoning.

Ask the model to trace one source, one guard, and one sensitive sink. Ground every claim in implementation evidence and keep disproved assumptions.

04 / Verification

Build the cheapest decisive oracle.

Reproduce on the exact version, include a positive control, test the direct boundary, and verify that the expected guard blocks a negative case.

05 / Impact

Separate a primitive from a vulnerability.

Require attacker-observable confidentiality, integrity, account, or code-execution consequences. UI oddities and hypothetical escalation remain explicitly limited.

06 / Disclosure

Publish only after coordination.

Give vendors time to investigate and patch. Public write-ups preserve the original target, evidence, root cause, remediation, and honest severity limits.
